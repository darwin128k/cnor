# Image robustness checks

The shared target exercises the public `cnor_vm_load` boundary with arbitrary
bytes, runs accepted images with a 512-instruction budget, resets and runs
again, reloads into the same VM and deinitializes twice. It checks that all
tracked lh allocations were released. There are no native imports, so images
that require a native stop at binding. Input is limited to 1 MiB and tracked
heap payload to 8 MiB; these are campaign resource limits, not format limits.
The lh allocator's configured failure policy still applies at the heap cap.

## Portable deterministic smoke test

```sh
cmake -S . -B build -DCNOR_BUILD_TESTS=ON -DCNOR_BUILD_FUZZ=ON
cmake --build build
ctest --test-dir build --output-on-failure
./build/fuzz/cnor_image_mutate
```

The runner constructs a valid minimal image without the source compiler,
tests every truncated prefix, every one-bit mutation, boundary byte values,
trailing garbage and 10,000 mutations from a fixed PRNG seed. It also accepts
an image filename to apply the same mutations to a richer seed. On Windows,
add `.exe` (and the configuration directory for multi-config generators).
Set `CNOR_FUZZ_REPRO` to a writable file path to save each input before testing
it; after a crash the file contains the last attempted input. This optional
mode adds disk I/O. Use libFuzzer's single-file invocation below for exact replay.

## ASan, UBSan and coverage-guided fuzzing (Unix, Clang)

```sh
cmake -S . -B build-fuzz -DCMAKE_C_COMPILER=clang \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo -DLH_LIBRARY_OPTION_LTO=OFF \
  -DCNOR_BUILD_TESTS=ON -DCNOR_BUILD_FUZZ=ON \
  -DCNOR_SANITIZERS=ON -DCNOR_LIBFUZZER=ON
cmake --build build-fuzz
ASAN_OPTIONS=detect_leaks=1 UBSAN_OPTIONS=halt_on_error=1 \
  ctest --test-dir build-fuzz --output-on-failure
mkdir -p corpus artifacts
build-fuzz/fuzz/cnor_image_mutate --seed corpus/minimal.tbc
for source in fuzz/seeds/*.cn; do
  build-fuzz/cli/cnor compile "$source" -o "corpus/$(basename "$source" .cn).tbc"
done
build-fuzz/fuzz/cnor_image_fuzz corpus -max_total_time=60 \
  -timeout=5 -rss_limit_mb=512 -max_len=65536 -artifact_prefix=artifacts/
```

Instrumentation covers cnor, lh and the executables, not just the harness.
`CNOR_LIBFUZZER` also enables ASan/UBSan. To check the VM-only configuration,
add `-DCNOR_BUILD_COMPILER=OFF` and use the minimal seed or images generated by
a separate full build. To check switch dispatch, add `-DCNOR_VM_COMPUTED_GOTO=OFF`.

Replay and minimize a saved libFuzzer reproducer:

```sh
build-fuzz/fuzz/cnor_image_fuzz artifacts/crash-EXAMPLE
build-fuzz/fuzz/cnor_image_fuzz -minimize_crash=1 \
  -exact_artifact_path=artifacts/minimized.tbc artifacts/crash-EXAMPLE
```

Translate confirmed failures into focused hand-built cases in
`tests/test_image_vm.c`, so regressions do not depend on a random campaign.
The checked-in source seeds cover calls, loops, strings, arrays, dictionaries
and exception handling. CI saves its evolving corpus and reproducers, runs
60-second campaigns for both dispatch modes and compiler configurations, and
tests Debug/Release on Linux and Windows. A bounded campaign is evidence about
the tested inputs, not a proof that every possible image is safe.

## Initial findings and runtime cost

The initial checks found three issues now covered by focused regression tests:
empty-section offsets could form pointers beyond the image; dictionary slow
handlers dereferenced values without checking their dictionary kind; and
`try_push` did not verify that its catch dictionary's 13 cells fit the frame.

The header and catch-slot checks run at load time. Dictionary type checks run
in the slow handlers; existing dictionary dispatch fast paths already check
the kind. On Windows x64 / GCC 16.1.0 / Release, a repeated interleaved A/B
comparison against the pre-change executable measured loop 137.09 -> 137.23 ms
and dictionary workload 58.56 -> 59.04 ms (minimum of five rounds, seven
iterations, two warmups). These differences, +0.1% and +0.8% in elapsed time,
are within the observed run-to-run variation. No execution speedup is claimed.
